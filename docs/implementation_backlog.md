# Zzxrobot 企业级改进实施清单

配套总体设计：[Zzxrobot 企业级改进总体方案](industrial_upgrade_plan.md)。

基线仓库：`/home/zzx/vision_guided_manipulation`。本清单使用 B01~B38 作为稳定任务编号。每个任务都要产生可检查的代码、配置或报告；“启动过一次”不算完成。

## 1. 使用规则

- 按依赖顺序做，不按编号一次并行创建全部空包。
- 每个任务独立中文提交，必要时一个任务拆成“实现”和“测试”两个提交。
- 新节点默认使用 `zzx` 命名空间，不覆盖旧节点；切换由 bringup profile 控制。
- 所有运动测试先使用假后端或仿真，真机测试单独记录机器人、工具、场景和操作者。
- 每个 Action 测正常、拒绝、取消、超时、反馈中断五类路径。
- 每个实验保存 commit、配置 hash、模型 hash、标定 ID、随机种子和结果。

完成定义：构建通过、包测试通过、验收场景通过、文档与实际一致、Git 状态中没有意外构建产物。

## 3. M0：冻结基线和修复确定性错误

### B01 冻结可复现环境

目标：让新机器能够明确知道安装什么、构建什么、预期哪些测试暂时失败。

产物：

- `ros2.repos` 或来源清单。
- `scripts/bootstrap_ubuntu.sh`，只安装声明依赖，不包含用户凭据。
- `docs/environment.md`，记录 Ubuntu、ROS、APT 包、Python lock、GPU/驱动可选项。
- `scripts/doctor.sh`，输出 ROS、DDS、GPU、磁盘、USB、网络和包发现结果。

验收：在干净容器或新 WSL 实例执行 rosdep、构建接口包和四个上游包；已知上游测试失败必须在文档列出，不能静默忽略。

建议提交：`工程：冻结 ROS 2 基线环境与依赖清单`

### B02 修复上游路径、控制器和测试基础

目标：去掉机器相关绝对路径，建立唯一控制器映射。

修改：

- 把 `six_arm.urdf` 改成 xacro 或通过 launch 注入控制器参数路径。
- arm controller 只含 joint1~6，gripper controller 只含 joint7/8。
- `mybot` 与 `mybot_description` 两套 MoveIt 配置确定唯一权威来源；另一套删除重复内容或明确只作上游归档。
- 修复全空字节 `test_flake8.py` 和 Cartographer 格式错误。

验收：`ros2 control list_controllers` 与 MoveIt controller manager 显示相同关节所有权；完整 `colcon test-result --verbose` 没有本任务引入的失败。

建议提交：`修复：统一 MoveIt 与 ros2_control 控制器配置`

### B03 建立 robot profile 与能力清单

目标：隔离六轴仿真和七轴比赛机器人的模型、关节、手、相机和后端能力。

产物：

- `configs/robots/zzx_sim_mobile_6dof.yaml`
- `configs/robots/competition_left_7dof_o10.yaml`
- JSON Schema 或等价严格校验。
- `zzx_profile validate/list/show` 命令。

验收：重复关节、未知工具、向量长度错误、非法 URL、占位标定在自动运行模式全部被拒绝；比赛 profile 不声称支持未知的轨迹透传和力控。

建议提交：`新增：建立仿真与比赛机器人的能力配置`

## 4. M1：接口与 C++ 执行主链

验收：C++/Python 构建和导入通过；消息构造、序列化、非法输入验证有测试；README 中有旧接口迁移表。

建议提交：`完善：补充目标质量与执行状态接口契约`

### B05 实现假机械臂后端

目标：不依赖 Gazebo 就能稳定复现正常、慢执行、拒绝、卡住、断反馈和取消。

产物：`zzx_execution` C++ 包中的 `FakeArmBackend`、脚本化故障参数和关节反馈发布。

验收：固定种子下每种故障可重复；假后端绝不连接现场 HTTP 地址。

建议提交：`新增：实现可注入故障的机械臂假后端`

### B06 实现 C++ `MoveArm` Action server

依赖：B04、B05。

实现输入校验、资源租约、计划、执行、反馈、settling 和结果。第一版 joint target 完整实现；pose target 在 MoveIt 接入前明确返回 UNSUPPORTED，不能伪成功。

验收：名称顺序变化仍按名字映射；NaN、重复名、未知名、越界、零/负缩放被拒绝；服务器初始化不产生运动。

建议提交：`新增：实现机械臂动作服务与目标校验`

### B07 实现执行监控与取消

依赖：B06。

监控关节误差、反馈年龄、控制器结果和稳定时间。取消必须传播到底层、停止新指令并确认停止；无法确认返回 STOP_UNCONFIRMED。

验收：取消、超时、反馈断开不会进入成功；目标到达但未稳定不会提前成功；continuous 关节使用最短角差。

建议提交：`新增：实现机械臂执行监控与取消确认`

### B08 实现幂等任务和结果持久化

依赖：B06。

使用 SQLite 或轻量持久化保存 task_id、payload_hash、状态、operation_id 和后端结果。物理请求超时进入 NEEDS_RECONCILIATION。

验收：同 ID 同参数 20 次并发只产生一个后端动作；同 ID 不同参数报冲突；进程在请求中断后重启不会自动重复动作。

建议提交：`新增：实现任务幂等与未知结果对账状态`

### B09 实现比赛 HTTP 假服务与契约测试

目标：把现场 8087/8088 的已知协议转换成可自动回归的服务。

假服务支持可配置 HTTP 200/400、延迟、断连、计划成功执行失败、错误标签和状态变化。契约测试校验请求数组顺序、prepare 流程和响应解析。

验收：复现历史 `Planning succeeded` 后 `Execution failed`、prepare 后成功和超时结果未知三类案例。

建议提交：`测试：建立比赛 HTTP 后端协议回归环境`

### B10 实现 HTTP ROS 2 适配节点

依赖：B07、B09。

复用已有 Python 客户端，形成独立后端节点；网络线程与 Action 回调分离。启动读取 capabilities，自动运行入口显式执行退出示教、控制模式和使能准备。

验收：网络阻塞不阻塞执行器其他回调；断线后 Action 明确失败；没有标准轨迹能力时拒绝 trajectory 模式。

建议提交：`新增：接入比赛机械臂与灵巧手 HTTP 后端`

### B11 建立 bringup、生命周期和单命令所有权

依赖：B06、B10。

新增 `zzx_bringup`，按 sim/fake/http profile 启动。建立 readiness gate、节点掉线处理和命令生产者唯一性检查。

验收：旧 `move_arm.py` 与新 server 不会同时启动；设备未就绪时任务入口不可用；节点重启不自动恢复物理动作。

建议提交：`新增：建立统一启动与机器人就绪管理`
