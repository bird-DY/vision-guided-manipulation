# B14 第一阶段：RGB-D 同步与输入质量核心

## 当前完成范围

新增 `zzx_camera/rgbd_gate.py` 和离线测试。核心不启动相机、不发送机械臂命令、不修改既有 launch。
**当前 camera_manager 尚未接入这个核心，因此启动原相机 launch 不会自动开启这层门控。**
这是 B14 的第一阶段，不是 B14 整体完成，也不是相机标定完成。

## 为什么加这一层

比赛现场“能看到画面、能识别灯色”不等于目标三维坐标可靠。
不同时间拍摄的彩色图和深度图，尤其在腕部相机运动时，会把某个像素匹配到错误的空间点。
订阅队列积压、相机掉帧、无效深度、旧会话数据，都应在定位之前被拦截。

已有 B13 StreamGuard 负责入口尺寸、CameraInfo、内参稳定性和流存活检查。
本模块增加成对时序与深度质量判定，不替代 B13，也不验证手眼标定或机器人可达性。

## 核心接口

- `GateConfig`：只读参数；非法值、非有限数或过大队列直接拒绝。
- `reset_session(session_id, timestamp_source, ros_ns, mono)`：开启明确的新会话，清空队列、时间历史和输出统计；丢弃早于会话边界的帧。
- `accept(kind, message, ros_ns, mono)`：接收 color/depth；通过时返回一个 FramePair，否则返回 None。
- `snapshot(ros_ns, mono)`：执行过期检查并返回状态、原因、丢弃计数、队列长度、最近合格帧的质量和年龄、输出帧率。

调用方必须串行使用此核心，并保证消息进入后不再修改其内容。返回的 FramePair 持有原消息引用。
时间戳比较使用整数纳秒；`mono` 是本地单调时钟秒数，不能用 ROS 时间替代。
不能将不同机器、不同时间域的时间戳未经同步直接比较。

## 默认门限与策略

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| max_delta_s | 0.03 s | 彩色和深度时间差上限 |
| max_age_s | 0.25 s | 接收及缓存帧的最大年龄 |
| input_timeout_s | 1.0 s | 任一输入流停止后的超时 |
| min_depth_m / max_depth_m | 0.15 / 3.0 m | 用于统计的有效深度范围 |
| min_valid_ratio | 0.6 | 全幅深度有效像素比例下限 |
| queue_size | 5 | 每个输入队列的容量上限 |

以上是软件基线值，不是 Gemini335 的精度承诺或全部有效工作范围；真实工位须用数据验证后配置。
按时间顺序匹配队首，不做插值、不复用帧、不等待全局最优最近邻。
两帧时间差过大时丢掉较旧的一帧；队列溢出也丢最旧帧，优先控制延迟。
FPS 根据最近两秒内、最多一百个合格输出的单调到达时刻估算，不代表相机标称采集帧率。

## 深度统计的边界

支持 `16UC1` 毫米和 `32FC1` 米，遵守 Image 的 `is_bigendian`、`step` 和行填充。
0、NaN、Infinity 和设定范围外的值不计入有效像素；65535 mm 在默认范围外，不会当成近处物体。
彩色和注册深度必须具有相同尺寸及 frame_id；不使用 resize 假装实现配准。
全幅比例只是入口指标：通过也不保证目标 ROI 深度有效，后续定位仍需局部深度统计和离群点处理。
相同 frame_id 也不能证明真实几何配准正确，仍依赖 B13 元数据验证和后续标定验收。

## 状态与恢复

- STARTING：尚无会话或正在等待两个输入流。
- READY：最近一对图像通过入口检查，**不代表允许运动**。
- DEGRADED：时间差、图像年龄、布局或深度比例不合格。
- ERROR：输入流超时，或时钟倒退。

流超时清空缓存，恢复后必须由新鲜图像重新组成一对。时钟倒退会锁存错误，必须显式新建会话。
即使 ROS 仿真时钟暂停，单调时钟仍能检测流停止。
最近合格输出一旦超过年龄门限，状态不再保留 READY。
所有输出的 `motion_eligible` 固定为 false；此模块不创建 ObjectTarget，不连接执行器。

## 时间来源

核心接受显式 synthetic 或 vendor_system 来源，拒绝 host_publish_time。
B13 synthetic 的发布时刻可在后续适配器确认 synthetic 后端后明确映射为 synthetic。
硬件 SDK 的主机发布时间不能冒充采集时间；接入硬件前须实现采集时间到 ROS 时间域的可信映射。
vendor_system 也只是时间域契约，不自动证明设备硬件同步；仍需测量时间差和实际动态误差。
